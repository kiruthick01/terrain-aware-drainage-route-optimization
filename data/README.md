# Data sources

Nothing in `raw/` or `processed/` is committed (see `.gitignore`); everything
below is re-downloadable or regenerated by the pipeline.

## DEM — `raw/chennai_velachery_dem.tif`

- **Source:** OpenTopography, SRTM GL1 (30 m), <https://opentopography.org>
- **Extent:** 80.1885–80.2579°E, 12.9482–13.0001°N (Velachery / South Chennai),
  EPSG:4326, 250×187 cells
- **How to re-download:** OpenTopography → Data → SRTM GL1 → select the bbox
  above → GeoTIFF. Rename the download to `chennai_velachery_dem.tif`.
  (Bhuvan/ISRO CartoDEM was tried first; portal too unreliable — see
  devlog/29-07-26.md.)
- **License:** SRTM is public domain (NASA/USGS); OpenTopography requests
  acknowledgment: "Data provided by OpenTopography, SRTM GL1 (NASA/USGS)."
- **Known issues:** elevations to −6 m near water bodies (SRTM artifact, not
  bathymetry); 30 m resolution smooths streets and micro-drainage.

## Rainfall — `raw/imd/rain/2015.grd` and `raw/rainfall_2015_sample.csv`

- **Source:** India Meteorological Department (IMD, Pune) gridded daily
  rainfall, 0.25°×0.25°, fetched via [`imdlib`](https://imdlib.readthedocs.io)
- **How to re-download:** delete `raw/imd/` and run the pipeline (below) —
  `fetch_rainfall` downloads automatically (~50 MB per year, network needed).
- **License:** IMD data is free for research/non-commercial use; cite
  Pai et al. (2014), *Mausam*, 65(1), for the gridded dataset.
- **Known issues:**
  - The zone's own 0.25° cell is sea-masked (nodata) in IMD's land mask;
    the pipeline substitutes the nearest valid land cell (13.00°N 80.00°E,
    ~25 km west) and applies it zone-uniformly.
  - Daily totals are 08:30–08:30 IST windows: the "Dec 1 2015" Chennai
    deluge appears as 349.6 mm on **Dec 2** in this dataset.

## Land use — `raw/osm_landuse.geojson` (Track B)

- **Source:** OpenStreetMap, fetched via [`osmnx`](https://osmnx.readthedocs.io)
  (Overpass API) — buildings, roads, water, and vegetation/landuse polygons
  within `zone_boundary.geojson`
- **How to re-fetch:** `python -m src.pipeline.landuse` (network required,
  ~45k features, ~1-2 min via Overpass). Not part of `pipeline.run` — this
  is Track B (HEC-RAS) input, not needed for the Track A proxy.
- **License:** © OpenStreetMap contributors, ODbL — attribution required in
  any published output using this data.
- **Known issues/assumptions:** see `src/pipeline/landuse.py` module
  docstring for the full classification and rationale. In short: cells with
  no matching OSM tag default to a generic "urban mix" class rather than
  open ground (Velachery's OSM tagging coverage is patchy, not empty), and
  the SCS Curve Number values assume Hydrologic Soil Group D throughout —
  no soil survey data exists for this zone.
- **Outputs:** `processed/landuse.tif` (classification, same grid as
  `dem_reprojected.tif`), `processed/curve_number.tif` (SCS CN, same grid),
  `processed/landuse_classes.csv` (class → Manning's n / CN lookup table).

## Generated — `raw/zone_boundary.geojson`

MVP stand-in boundary: a rectangle of the DEM's own extent, produced by
`python -m src.pipeline.make_zone_boundary`. Replace with a hand-drawn
polygon later; the pipeline picks up whatever geometry the file holds.

## Regenerating `processed/`

```bash
python -m src.pipeline.make_zone_boundary   # once, if boundary missing
python -m src.pipeline.run                  # everything else
```

Outputs: `dem_clipped.tif`, `dem_reprojected.tif` (EPSG:32644), `slope.tif`,
`aspect.tif`, `dem_filled.tif`, `flow_dir.tif`, `flow_acc.tif`,
`scenarios.json`.
